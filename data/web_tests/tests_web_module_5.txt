УРОК 17: Интеграции с внешними API
────────────────────────────────────────────────────────────

ВОПРОС 1
Что такое API и какую главную проблему решает его использование в AI-приложениях?

1. API — это визуальный редактор для создания промптов без кода
2. API — это интерфейс для получения актуальных внешних данных, которых AI не имеет в своих знаниях ✅
3. API — это способ ускорить генерацию текста моделью Gemini в 10 раз
4. API — это система авторизации пользователей в Google AI Studio

Пояснения:
1 ❌ Визуальный редактор промптов — это функция интерфейса Google AI Studio. API — про доступ к данным и сервисам внешних систем, а не про редактирование промптов.
2 ✅ Верно! AI без API знает только то, что было в данных обучения. Интеграция с API погоды, новостей, курсов валют даёт AI актуальные данные в реальном времени. Вопрос "какая погода в Москве?" с API — точный ответ, без API — "мои данные устарели".
3 ❌ Скорость генерации Gemini определяется серверами Google и не зависит от подключения внешних API. Каждый API-запрос скорее добавляет небольшую задержку.
4 ❌ Авторизация пользователей — отдельная функция приложения. Хотя некоторые API используют ключи (API Key), это не их главное назначение — они прежде всего предоставляют данные и сервисы.

ВОПРОС 2
Что такое mashup-приложение и в чём его отличие от приложения с одним API?

1. Mashup — это приложение с анимированным splash-экраном при загрузке
2. Mashup — это приложение, объединяющее данные от нескольких API для создания комплексного ответа ✅
3. Mashup — это приложение, работающее одновременно на нескольких языках программирования
4. Mashup — это тип приложения, который не требует API-ключей

Пояснения:
1 ❌ Splash-экран — это визуальный элемент загрузки. Mashup — архитектурная концепция, означающая объединение нескольких источников данных, а не визуальный эффект.
2 ✅ Верно! Пример из урока: "Посоветуй, стоит ли ехать в Барселону?" — AI обращается к Weather API (погода) и News API (события, забастовки) одновременно, объединяет данные и даёт комплексную рекомендацию. Это и есть mashup.
3 ❌ Количество языков программирования не определяет тип приложения. Mashup — про источники данных, а не про технологический стек.
4 ❌ Тип аутентификации не определяет mashup. Некоторые бесплатные API не требуют ключей, но это не делает их mashup автоматически. Mashup — про объединение нескольких API.

ВОПРОС 3
Почему для учебных проектов рекомендуется начинать с публичных API без ключей (AdviceSlip, Dog CEO, Random User)?

1. Эти API работают быстрее всех остальных и имеют лучшее качество данных
2. Они позволяют сосредоточиться на логике интеграции без риска утечки ключей и без регистрации ✅
3. Платные API запрещены к использованию в Google AI Studio
4. Публичные API не имеют ограничений по количеству запросов, а все остальные имеют лимиты

Пояснения:
1 ❌ Скорость и качество данных у разных API разные. AdviceSlip, Dog CEO — это простые демо-API. Настоящие API погоды или новостей могут быть точнее, но требуют ключей.
2 ✅ Верно! Учебная цель — освоить паттерн fetch → обработка JSON → отображение. Публичные API позволяют сделать это сразу, без регистрации и без риска случайно опубликовать API-ключ. После освоения паттерна легко перейти к реальным API.
3 ❌ Google AI Studio не ограничивает, какие внешние API использовать. Разница только в том, что ключи нельзя хранить в коде напрямую — нужно чтобы пользователь вводил свой ключ.
4 ❌ Многие публичные API без ключей всё равно имеют лимиты (по IP, по времени). А некоторые платные API предоставляют очень большие бесплатные лимиты (OpenWeatherMap — 1000 запросов/день).

ВОПРОС 1
Какой принцип лежит в основе всего курса и итогового проекта GovAssist Pro?

1. Писать весь код вручную и использовать AI только для проверки
2. Создавать AI-приложения через текстовые описания в промптах — "95% промпты, 5% код" ✅
3. Изучить JavaScript и Python перед созданием любого приложения
4. Использовать только платные корпоративные инструменты, а не бесплатные API

Пояснения:
1 ❌ Ручное написание кода — это традиционный подход разработки. Курс строится на противоположном принципе: описываем что хотим получить в промпте — AI создаёт код за нас. Консоль и Code-режим — только для просмотра.
2 ✅ Верно! Методология курса с урока 2: вся логика, интерфейс, обработка ошибок, тесты — всё описывается через текстовые промпты. Разработчик описывает ЖЕЛАЕМЫЙ РЕЗУЛЬТАТ, AI генерирует реализацию. Именно это позволяет создавать сложные приложения без опыта программирования.
3 ❌ Курс специально создан для госслужащих, аналитиков и менеджеров без опыта программирования. Знание JavaScript или Python не требуется — промпты на естественном языке заменяют написание кода.
4 ❌ Урок 17 прямо рекомендует начинать с бесплатных публичных API. Итоговый проект использует бесплатные API (ExchangeRate, AdviceSlip). Курс ориентирован на доступность, а не на платные инструменты.

ВОПРОС 2
Почему итоговый проект GovAssist Pro реализован как многорежимное приложение (5 режимов), а не как один универсальный чат?

1. Технические ограничения Google AI Studio не позволяют создать одно универсальное окно для всех задач
2. Разные задачи требуют разного интерфейса: работа с документами, генерация текстов и чат — принципиально отличаются ✅
3. Многорежимность нужна только для красоты — функционально один чат сделал бы всё то же самое
4. Каждый режим обращается к разной версии модели Gemini

Пояснения:
1 ❌ Google AI Studio технически позволяет создать любую структуру интерфейса. Выбор многорежимной архитектуры — это осознанное UX-решение, а не техническое ограничение.
2 ✅ Верно! Анализ документа требует drag-and-drop зоны и чекбоксов типа анализа. Генератор письма требует полей "Кому", "Тема", выбора тона. Чат требует истории сообщений. Каждый режим оптимизирован под свою задачу — это и есть профессиональное UX-решение.
3 ❌ Один чат потребовал бы от пользователя помнить и вводить все параметры вручную. Специализированные интерфейсы снижают когнитивную нагрузку и уменьшают количество ошибок. Режимы — это не украшение, а функциональная необходимость.
4 ❌ Все режимы используют одну и ту же модель Gemini с разными системными промптами. Разграничение на режимы — это архитектура интерфейса, а не разграничение моделей.

ВОПРОС 3
Что означает концепция "Code режим как музей" применительно ко всему курсу и итоговому проекту?

1. Код приложения нельзя сохранять или экспортировать — он существует только внутри платформы
2. Код изучается и просматривается для понимания, но все изменения вносятся исключительно через промпты ✅
3. Готовый код нужно хранить в музее данных на сервере Google
4. После завершения курса код приложений становится публичным достоянием

Пояснения:
1 ❌ Код можно скачать (Download ZIP) — это описано в уроке 4. Метафора "музей" означает отношение к коду: смотрим и изучаем, но не редактируем руками.
2 ✅ Верно! На протяжении всего курса принцип неизменен: открыть Code-режим, найти интересный паттерн (кэширование, ленивая загрузка, тест-раннер) — посмотреть, понять логику. Но исправить баг или добавить функцию — только через новый промпт. Это сохраняет целостность архитектуры и подходит людям без опыта программирования.
3 ❌ "Музей данных на сервере Google" — это несуществующая концепция. Метафора музея описывает отношение разработчика к сгенерированному коду: наблюдение и изучение без вмешательства.
4 ❌ Проекты в Google AI Studio остаются в аккаунте пользователя. "Музей" — метафора подхода к работе с кодом, а не информация о правах доступа к нему.
